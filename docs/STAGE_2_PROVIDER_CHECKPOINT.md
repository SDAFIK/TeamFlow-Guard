# Stage 2 provider checkpoint

Gemini remains the only exposed model for persisted recovery proposals. The existing proposal source constraint does not yet accept OpenAI. A provider-neutral server adapter is now used by the Gemini recovery path, with an isolated OpenAI Responses adapter tested against mocked transport. OpenAI is disabled unless TEAMFLOW_OPENAI_ALLOW_PAID=true, OPENAI_API_KEY and OPENAI_MODEL are present. Do not set that flag under the current no-paid-services rule. No automatic provider failover; rules remain explicitly labeled. The OpenAI adapter uses strict structured output, server-side validation, refusal/incomplete handling, bounded input/output, timeout and sanitized errors. No API keys or calls in CI. A reviewed migration and truthful source/audit metadata plus end-to-end tests are required before exposing OpenAI in the API/UI. Actual Gemini activation and real provider acceptance remain pending.
Reference: https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses
