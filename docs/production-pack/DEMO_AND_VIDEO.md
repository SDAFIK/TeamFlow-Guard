# Competition Demo and 180-Second Video

## Demo principle

The strongest proof is a real browser interaction: a CI source signal leads to a explainable graph impact; an AI plan is generated from evidence; a manager reviews and approves; the database persists the change; the audit reflects the actor and diff. Avoid implying that an AI-generated cinematic clip is a working product.

## Setup

- Seed fictional Checkout Launch workspace with six team members and all four risks.
- Use a reproducible reset command limited to the demo workspace.
- Prepare two browser roles: a viewer (can inspect, cannot approve) and a manager (can approve). No public admin passwords in repository.
- Have a valid AI model provider key and acceptable quota, **or** explicitly label the precomputed sample plan.
- Pre-record a genuine screen capture of the working app for video; use animation only for conceptual transitions and opening, not proof of execution.

## Camera/editor notes

- Record the actual browser at 1080p or better, hide personal tabs/keys and enable cursor highlight.
- Use readable screen zoom. Cut waiting time transparently; do not fabricate successful transactions.
- Keep music low and captions legible. Narration should say *can*, *is designed to*, or *demonstrates* for unmeasured benefits—not invented performance numbers.
- Include very short clear labels: `Evidence`, `Impact`, `AI proposal`, `Human approval`, `Audit`.
- A visible "Demo workspace" badge prevents confusing fictional test data with real customer operations.

## Judge Q&A — facts to be able to demonstrate

1. **Why not just Slack/GitHub?** Individual tools show their own signals; TeamFlow Guard computes cross-task impact and creates a bounded, human-reviewed action plan with evidence and audit.
2. **Why AI?** Deterministic rules detect risks; AI synthesizes plausible recovery options across constraints. A simple if/else engine cannot reliably generate contextual tradeoffs, but AI cannot be the authority on facts.
3. **What if AI is wrong?** Schema/ID/action validation and human approval prevent unreviewed changes. Show a rejected proposal.
4. **What is actually integrated?** Show connected badge and source IDs; identify seed/test sources clearly. Do not claim GitHub live sync if only demo fixtures exist.
5. **How will it scale?** Explain tenant isolation, measured API cost/latency, idempotent event processing and progressive integrations; do not assert load-test numbers unless measured.
